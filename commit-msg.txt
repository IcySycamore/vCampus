refactor(server): 成绩改按需查询，通用层补 JdbcQuery，启动不再写业务数据

全量加载（ADR-0011）
- ScoreStore 去掉 loadAll，换成 find / findByStudent / findByCourse 三条按需查询；
  ScoreDao 不再持有全量成绩 Map，只留参数校验与回填 scId
- 通用层新增 JdbcQuery（list / one / number / update + RowMapper）：此前只有 DbHelper（连接）
  与 JdbcSupport（事务、可空参数），没有查询支持，逼得每个 DAO 各自抄一遍 try/finally

启动不再写业务数据
- CourseModule 删除 seedCatalog / seedClassroom / seedCourse / seedDemoClaim / firstUnclaimed：
  学院、教室、三门课不再由服务端在启动时 upsert
- 三处 provisionExisting（Course / Student / Library）删除
- 演示课表改为直接以行形式写进本地数据库（不入仓库，建库脚本里既无 INSERT 也无演示 uuid）

引导账号导入顺序（真缺陷，被启动种子长期掩盖）
- AdminAccountBootstrap.seed 从 AuthModule.initialize 拆成 AuthModule.bootstrapAccounts()，
  由 VCampusServerApp 在各模块登记完开户钩子之后调用
- 原因：引导文件里可写任意角色的账号（集成测试就把「学生」写进 admins.tsv），提前导入时
  这些账号拿不到学籍/读者/课程档案；老代码靠启动时回头补档来补这条缝

学院是课程模块的前置引用行
- tblCourseStudent.cstCollegeUuid / tblTeacher.tcCollegeUuid 都是非空外键指向 tblCollege，
  库里没有学院时新建档案会被数据库拒（1452），进而导致整个开户回滚
- CourseModule.DEFAULT_COLLEGE_UUID 公开；会注册或引导师生账号的四个集成测试各自准备一行学院
  （名字用「默认学院」，避开 CourseStoreJdbcTest 占用的 clgName 唯一键）

其它
- VCampusServerApp 合并 startServer 与 runServer：装配体直接在 startServer 里，删掉那层转发
- 删除错位包里的垃圾：edu.seu.vcampus.model.User 及其测试、edu.seu.vcampus.dao.DbHelperTest
  （后者是吞异常的假测试，没数据库也照样绿；server/db 下已有真正的 DbHelperTest）

验证：mvn -B -ntp clean verify，719 测试全绿（common 136 / client 334 / server 249）。
