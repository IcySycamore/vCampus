# 图书馆借阅额度与验收


## 业务规则

| 登录身份 | 同时未归还上限 | 满额界面示例 |
| --- | --- | --- |
| 学生 | 30 本 | 已借 30/30 本 · 剩余可借数量：0 本 |
| 教师 / teacher（英文不区分大小写） | 30 本 | 已借 30/30 本 · 剩余可借数量：0 本 |

身份来自服务器认证会话。学生和教师建号时自动建立图书馆账户，默认上限为 30 本。客户端使用登录响应确认的角色显示默认额度；服务器使用 token 对应的 UUID 查询图书馆账户并以账户保存的 `borrowLimit` 为准，忽略客户端自填的发送者。管理员只管理馆藏，不建立普通读者账户；未知角色没有借阅权限。

仅 `returnedAt == null` 的记录占用额度，逾期但未归还仍占用；已归还的历史记录不占用。剩余额度为 `max(0, 上限 - 未归还数量)`，已有数据超过上限时显示实际已借数量、剩余 0 本，并拒绝继续借阅。额度不等于某本书的库存，服务器仍会检查库存和重复借阅。

服务器在 `LibraryReaderCommands` 中校验，超限返回 400 与“最多同时借阅 30 本图书，请先归还后再借阅”。查询借阅数量失败时不继续借书，返回 500。借书和归还后重新查询记录，不在客户端自行推算或减少数据库库存。

## 界面行为

- 图书馆底部持续显示已借数量、上限和剩余数量，不受搜索结果提示覆盖。
- 首次进入或刷新记录时显示“已借 —/30 本 · 剩余可借数量：待刷新”，暂时禁用借书按钮。
- 加载成功且有额度时启用“借阅所选”；满额、超额、未登录和断线时禁用。
- 借书或还书请求处理中禁用借书按钮；收到响应后重新查询记录。失败响应也会触发记录刷新，以校正其他窗口操作造成的额度变化。
- 仅最新借阅查询的响应用于更新额度，避免迟到的旧响应重新启用满额按钮。
- 离线预览不生成虚构借阅数据，显示“登录并连接服务器后查看借阅额度”。

界面限制用于引导操作；服务器的规则才是最终依据。`common.library.LibraryPolicy` 定义新账户的默认额度，实际服务端限制读取 `LibraryAccount.borrowLimit`。修改全局默认值时更新策略；调整单个账户时通过 `LibraryAccountDao.update` 保存。

## 真实数据库联调状态

当前不能完成“正式入口启动 → 真实登录 → 数据库持久化借还”的完整验收：

1. 正式 `main` 入口已注入四个 `XxxDaoMemory`，注册到同一分发器并复用认证会话表，可用于内存态演示。
2. JDBC 持久化尚未接入；数据库同学需在 `DbHelper` 合入后新增 `XxxDaoJdbc` 并替换入口中的 Memory 实例。

数据库实现方需提供具体 DAO，并向正式入口传入组装后的业务服务。自动化流程测试已经启动正式双端入口、执行真实认证和 Socket 借还，但数据库业务服务使用测试替身；测试通过不等同于真实数据库联调通过。

数据库侧交付参见 [数据库接口对接](library-database-interface.md)。完整服务会在业务层再次检查图书馆账户状态和额度，当前数量检查与借还操作仍通过同一 JVM 的锁保护；多个服务器进程或其他数据库写入路径，需要数据库侧进一步提供同一事务内的原子额度保障。

## 对接完成后的人工验收步骤

使用独立测试账户和可恢复的测试馆藏，分别准备学生、教师账户及至少 31 本可借图书：

1. 正式启动服务器，用真实账户登录；核对身份、未归还记录和页面额度与数据库一致。
2. 学生和教师分别从 0 本逐次借到 30 本；每次确认记录新增一次、库存减少一次、显示和剩余额度同步变化。
3. 满额时确认借书按钮禁用；通过另一个客户端或直接协议请求尝试超限，必须返回 400，数据库记录和库存不得变化。
4. 归还其中一本；确认归还时间落库、库存增加、历史记录保留、剩余额度恢复 1 本且借书按钮可用。
5. 再借一本，确认成功且再次满额。退出重登，核对数量保持一致。
6. 验证已归还历史记录不计入、逾期未还仍计入；模拟数据库故障，确认请求失败且不产生半完成的库存或记录更新。
7. 同一账户两个连接争用最后一个名额，只能成功一次；如实际部署多个服务器进程，还必须跨进程重复这一项。

记录服务器版本、数据库版本、测试账户、初始/最终记录与库存以及失败日志；完成这些步骤后才能标记真实数据库验收通过。
