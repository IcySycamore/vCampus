# 设计约定（模块实现指南）

> 给**还没开始写自己模块**的人看。十分钟读完，照着 user / student 模块的骨架改个名字就能开工。
> 规则的可执行版本见 `docs/adr/0009-client-api-conventions.md`，六模块完整设计见 `docs/客户端API与前端映射设计.md`。

---

## 0. 一句话总结

**公共工程出契约与数据载体；每个业务模块在自己包里提供「逻辑 API」；界面只做「功能 → 控件」的对应。**

```text
common.<业务>/{entity,dto}     ← 双端共享的数据载体（唯一一份定义）
common.message               ← Message 信封 / PageResponse / BatchResult / 三个契约接口
server.<业务>/               ← Module(装配) + MessageHandler(协议适配) + Service(业务) + Dao(数据)
client.<业务>/               ← XxxService(逻辑 API) + XxxModule(装配)
client.view.<业务>/           ← 页面（只接线，不写业务判断）
```

---

## 1. 契约层（common）

| 约定 | 说明 |
| --- | --- |
| 命令码分段 | 100 用户 / 200 学籍 / 300 选课 / 400 图书馆 / 500 商店 / 600 银行；常量写在 `Command`，**只能追加** |
| 状态码 | 复用 `StatusCode`：200/400/401/403/404/500 + 业务码（P100 口令错、P102 禁用、B100 未开户）。**不要自造新的四不像码** |
| 载荷 | 一律用显式 DTO 类，**不要用裸 `String`/`Number`/`String[]`**（现有图书馆 400 命令用 `String[]`，靠 `ClassCastException` 兜底，是反例） |
| 分页 | 列表类查询用 `PageResponse<T>{items,total,pageNumber,pageSize}`；请求侧 `pageNumber/pageSize` 默认 1/20、上限 100 |
| 批量 | 用 `BatchResult{successCount,failures}`：**逐条执行、逐条记账，不做全批回滚**（导入几十条时一条重名不能让整批失败） |
| 权限 | 能力写在 `Capability`，映射写在 `Permissions.can(role, cap)`；**双端共用同一份**，界面拿它决定控件可见性 |
| 身份 | 跨模块引用用户**一律 uuid**；各模块自己的记录主键只用于「管理操作指定目标」 |

## 2. 服务端模块骨架（照抄 `server.user` / `server.student`）

```java
public final class XxxModule {                      // ① 自装配入口
    public static void register(ServerMessageDispatcher dispatcher, SessionManager sessions,
            AccountProvisioning provisioning) {     // 需要开户就收 provisioning，不需要就去掉
        XxxDao dao = new XxxDaoMemory();            // 暂用内存实现，接口先定死
        XxxService service = new XxxService(dao);
        XxxMessageHandler handler = new XxxMessageHandler(service, sessions);
        dispatcher.register(Command.XXX_ONE, handler);
        provisioning.add(new XxxProvisioner(dao));  // 若该模块有「建号即建档」的表
    }
}

public class XxxMessageHandler implements MessageHandler {   // ② 协议适配，只有分支与错误码
    @Override
    public void handle(Message request, MessageSender sender) {
        SessionEntry entry = requireCapability(request, sender, Capability.XXX);  // 401/403 在这里回
        ...
        sender.send(response);      // 响应由处理器主动发送，方法不抛受检异常
    }
}
```

要点（每条都有踩坑来源）：

1. **身份只从 `SessionEntry` 取**，绝不用 `Message.sender` —— 那是「发送方标识（预留）」，客户端随便填就能冒充别人（图书馆模块现状即为反例，正在修）。
2. **鉴权两层**：先 `Capability` 准入，再在 Service 里按会话收窄数据范围（教师只能看自己授的课）。
3. **禁止静默降级**：越权查询要回 403，**不能**悄悄改写成「只返回你自己的」——那会让调用方以为拿到了全量。
4. **开户**：一账号一行的档案表（学籍、将来的银行账户）用 `AccountProvisioner`；行为记录表（借阅/选课/订单）**不要**预建空行。任一模块建档失败会回滚并撤销账户。
5. **DAO 先接口后实现**：`XxxDao` 接口 + `XxxDaoMemory` 占位，JDBC 实现后补，Service 不用改。

## 3. 客户端模块骨架（照抄 `client.user`）

```java
public class XxxService {                           // ① 逻辑 API：界面只认它
    public PageResponse<Xxx> search(XxxQuery query) {          // 同步阻塞
        return page(call(Command.XXX_SEARCH, query).getData()); // 内部才认识 Message/Command
    }
}

public final class XxxModule {                      // ② 自装配，与 server 的 XxxModule 同名同形
    public static XxxService register(ClientMessageDispatcher dispatcher) {
        XxxService service = new XxxService(dispatcher);
        dispatcher.addConnectionListener(service);  // 需要「会话随连接失效」就登记
        return service;
    }
}
```

| 约定 | 说明 |
| --- | --- |
| 形态 | **一个具体类**，不做接口+实现分离；方法名是业务动作（`listUsers`/`searchBooks`/`recharge`） |
| 异常 | 失败抛**非受检** `ApiException`（文案统一走 `ApiErrors`）。方法签名**不声明**受检异常 |
| 分轨 | 「我的」方法**不带身份参数**（服务端从会话解析）；管理方法显式传目标；受限管理传资源条件（如 `courseUuid`） |
| 线程 | 页面用 `UiTasks.run(task, onSuccess[, onFailure])` 调；页面里不写线程、不写 `try/catch` |
| 装配 | `ClientApis.create(dispatcher)` 汇总；沿 `connect() → LoginFlow → MainFrame → MainContentPanel` 传，**每个页面只拿自己那一个 API** |
| 页面 | 只做「建控件 + 绑事件 + 调 API + 回填」；回填抽成纯函数（如 `LibraryTableModels`）便于单测 |

## 4. 查询三轨规则（最容易写错的地方）

| 轨道 | 方法形态 | 范围来源 | 准入 |
| --- | --- | --- | --- |
| 我的轨 | 无身份参数 | 会话 | 仅需登录 |
| 全量管理轨 | 显式传目标/条件 DTO | 参数 | `Capability` |
| 受限管理轨 | 显式传**资源**条件 | 资源 + 会话 | `Capability` 准入，Service 按会话收窄 |

同一命令码可承载两轨（靠 DTO 里的身份字段是否为空 + 调用者角色区分）；只有**响应类型真的不同**才新增码（如 201 取一条 vs 208 分页检索）。

## 5. 硬约束与提交前自检

| 约束 | 检查方式 |
| --- | --- |
| Java 7 语法（禁 lambda/stream/新 API） | `-source 1.7` 编译期拦截 |
| 每文件 ≤ 200 行、行宽 ≤ 100、类与 public 方法有 Javadoc | `mvn checkstyle:check` |
| 不留 TODO/FIXME/XXX | 同上 + `check_pr_completeness.py` |
| 改动必有测试，或写进 PR body 的「对应测试」 | 同上 |

```bash
mvn -B clean test          # 构建 + 全部测试（提交前必跑；clean 不可省，残留 class 会报 NoClassDefFoundError）
```

测试要求（ADR-0005）：

- **模块 API 是主战场**：同包假分发器（仿 `client.user.UserServiceTest.FakeDispatcher`）断言「方法 → 命令码 + 载荷」与「状态码 → 异常」
- **不写 GUI 自动化**：页面「薄」是它的替代保障；回填逻辑抽纯函数单独测
- **服务端**：Service 单测（内存 DAO）+ Handler 单测（假 `MessageSender`）
- **集成测试**：真实 socket，账号用 `-Dvcampus.users.file/-Dvcampus.admins.file` 指到临时文件，**不要污染工作目录**
