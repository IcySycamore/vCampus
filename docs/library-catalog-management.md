# 管理员图书馆藏管理


## 身份与界面

认证会话角色为“管理员”或 `admin`（英文不区分大小写）时，图书馆出现“馆藏管理”标签页。可按关键词查询全部馆藏（含已下架）、录入新书、选择图书修改资料和数量、下架所选图书。学生、教师及其他身份没有管理入口，服务器也会对四条管理命令逐条校验权限，伪造 sender 无效。

离线或身份失效时不能执行管理操作。提交期间暂时禁用管理按钮和表单，收到成功响应后自动刷新馆藏列表与普通检索；失败时显示服务器中文提示并恢复编辑。

## 管理操作

- **录入图书**：填写 ISBN、书名、作者、分类和馆藏总数，点击保存。ISBN 使用既有格式校验，书名最多 200 字符，作者/分类最多 100 字符，均不能为空；总数允许 0 至 Integer.MAX_VALUE。相同 ISBN（含已下架图书）不能重复录入。新书可借数量由服务器设为总数，初始未下架，忽略客户端提交的可借数量和下架标记。
- **修改馆藏**：选中图书后编辑书名、作者、分类和总数。ISBN 是查询键，不可修改。服务器锁定图书，按 `未归还数量 = 原总数 - 原可借数量` 计算；新总数不得小于未归还数量，新可借数量为 `新总数 - 未归还数量`。既有借阅记录保留，下架状态保持不变，不能通过修改资料偷偷重新上架。
- **下架图书**：选择图书并确认下架。逻辑标记 `withdrawn = true`，保留图书资料、库存和借阅历史，不物理删除。普通检索不显示，下架后不能继续借出，已借出的仍可正常归还。管理员查询仍可看到“已下架”状态；重复下架按成功处理。本次未提供重新上架操作。

## 消息协议

2026-09-13：馆藏扩展改用 408～411，保留 404～406 给团队设计中的续借/维护/借阅管理命令；双端须同时更新。

所有请求使用同一登录连接并携带 token；响应保留 uid 和命令号。

| 命令码 | 常量 | 请求 data | 成功 data |
| --- | --- | --- | --- |
| 408 | LIBRARY_CREATE_BOOK | Book（ISBN、资料、总数） | 服务器保存的新 Book |
| 409 | LIBRARY_UPDATE_BOOK | Book（固定 ISBN、修改后的资料和总数） | 计算可借数量后的 Book |
| 410 | LIBRARY_WITHDRAW_BOOK | `BookRef {isbn}` | 已标记下架的 Book |
| 411 | LIBRARY_CATALOG_SEARCH | `BookQuery`（关键词、范围、页码、每页数量） | `PageResponse<Book>`，含已下架及总数 |

状态码与命令号是独立字段：200 成功，400 参数/重复 ISBN/数量约束错误，401 未登录，403 非管理员，404 图书不存在，500 数据库或未预期错误。

公共 `Book` 新增 `withdrawn` 布尔字段，默认 false；保留原 serialVersionUID，并测试对象流能够传递该状态。客户端和服务器应一起更新以支持新增管理命令及下架规则。

## 数据库同学需实现的接口

本次没有编写 SQL、建表脚本或具体 DAO。`BookDao` 新增：

| 方法 | 实现责任 |
| --- | --- |
| searchCatalog(query) | 按 `BookQuery` 分页查询全部馆藏含下架，并返回准确 total，查询连接由 DAO 管理 |
| insertBook(connection, book) | 原子新增，ISBN 唯一，重复返回 false（含并发重复） |
| updateBook(connection, book) | 在已锁定记录上修改资料、总数和可借数量，保持 ISBN、下架状态和借阅历史 |
| withdrawBook(connection, isbn) | 在已锁定记录上标记下架，保留库存和历史 |

数据库需映射 `Book.withdrawn`。既有 `search` 只返回未下架图书，业务服务再次过滤；`findByIsbn` 包含下架记录，必须锁住目标行直到事务结束。借书、管理修改和下架共享该行锁；`adjustAvailable` 对下架图书禁止负向借出，但仍允许正向归还。所有写操作必须复用传入连接，不得自行提交、回滚或关闭它。

`LibraryCatalogService` 管理事务，在读锁定记录后校验、写入并提交，失败回滚。查询键、可借数量和下架状态不能仅依靠客户端约束。跨进程的锁、库存约束及并发唯一性需通过真实数据库集成测试确认。

正式入口通过 `LibraryModule.register` 注册 400～404、408～416，当前注入四个 `XxxDaoMemory` 占位实现。数据库同学后续新增 `XxxDaoJdbc`，通过 `DbHelper` 取得连接并替换入口依赖即可，不用修改 `LibraryService` 或网络分发器。

## 测试与验收

- `LibraryCatalogServiceTest`：录入、重复 ISBN、总数边界、服务端计算可借数量、下架和回滚。
- `LibraryCatalogPermissionTest`：非管理员的四条命令全部返回 403；格式错误在打开数据库连接前拒绝。
- `LibraryWithdrawalBorrowTest`：普通检索过滤下架书、禁止再借、允许归还。
- `LibraryCatalogPanelTest`：角色入口、已下架状态显示、录入/修改发送、处理中禁用与失败恢复。
- `LibraryEntityTest`：下架状态的对象流传输。

当前 DAO 仍是接口，自动化测试使用测试替身。真实数据库交付后，需要使用管理员账户完成录入 → 学生借出 → 管理员调整数量/下架 → 学生归还 → 退出重登验证持久化，并检查并发下架与借出不能同时成功。本次功能测试通过不等同于真实数据库验收通过。
