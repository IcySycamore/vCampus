---------------------------------------------------------------------
一、这份文档解决什么问题
---------------------------------------------------------------------

一句话：教你用最少的步骤，验证「客户端」和「服务端」真的能连上、能来回通信。

在只有一个模块的单元测试时，我们只能证明「这个类自己逻辑对」；但两个模块
拼在一起时经常出问题（字段名不一致、命令码不一致、超时设置对不上、序列化
丢数据……），这类问题只有把两端真连起来才暴露得出来。本说明就是干这个的。


---------------------------------------------------------------------
二、名词：什么叫「双端」
---------------------------------------------------------------------

「双端」= 客户端（vcampus-client）+ 服务端（vcampus-server）。

双端测试 = 真起一个服务器进程/线程，再用真的客户端网络代码连上去，
          发真实命令、收真实响应，全程不用替身（mock）。

和普通单元测试的区别：
  - 单元测试：直接 new 一个 Handler，喂一个假的 sender，断言返回值。
  - 双端测试：走 TCP、走序列化、走线程池、走分发器，端到端跑一遍。


---------------------------------------------------------------------
三、【重要】当前能跑通的双端路径
---------------------------------------------------------------------

目前有两条路，但只有第一条是通的，务必先看清楚：

  (1) 自动化双端测试 .......... 可用，就是本文重点（第五章）
  (2) 手动启动 UI 联调 ........ 暂不可用，见第六章原因

原因：客户端的网络层（ClientSocket 等）已经由 client 组实现并通过测试，
      但界面层（LoginFrame 等）还没有把「点登录按钮」接到 ClientSocket 上，
      目前整个工程里没有任何一处 new ClientSocket(...) 的界面代码。
      也就是说：现在启动 UI，点登录不会真的发消息给服务器。

所以现阶段想验证双端，请直接跑第五章的自动化测试。

四、准备工作
---------------------------------------------------------------------

必需环境：
  - JDK 8（本项目编译目标为 1.7，禁用 lambda/stream/var，请勿用高版本 JDK 编译）
  - Maven 3.6 以上

确认环境（PowerShell）：
  java -version        # 应输出 1.8.x
  mvn -v               # 应输出 Apache Maven 3.x

如果你的机器上 JDK 不是 8，或者 Maven 不在 PATH 里，先在本终端临时设置
（下面路径换成你自己的，只对当前终端窗口生效）：

  $env:JAVA_HOME='D:\Tools\jdk8u502-b07'
  $env:Path="$env:JAVA_HOME\bin;D:\Tools\apache-maven-3.9.16\bin;$env:Path"

Linux / macOS / Git Bash 用：
  export JAVA_HOME=/path/to/jdk8
  export PATH="$JAVA_HOME/bin:/path/to/maven/bin:$PATH"


---------------------------------------------------------------------
五、操作一：跑自动化双端测试（推荐）
---------------------------------------------------------------------

第 1 步：进入仓库根目录（注意是 vCampus 子目录，不是最外层）

  cd <你的路径>/vCampus-main/vCampus

第 2 步：跑全部测试（会顺带把双端测试也跑掉）

  mvn test

预期结果最后几行类似：

  [INFO] Tests run: 17, Failures: 0, Errors: 0, Skipped: 0    (common)
  [INFO] Tests run: 45, Failures: 0, Errors: 0, Skipped: 0    (client)
  [INFO] Tests run: 37, Failures: 0, Errors: 0, Skipped: 0    (server)
  [INFO] BUILD SUCCESS

只要看到 BUILD SUCCESS 且 Failures/Errors 都是 0，双端就是通的。


第 3 步（可选）：只跑双端测试，快一些

  mvn test -pl vcampus-server -am "-Dtest=ClientServerIntegrationTest" "-Dsurefire.failIfNoSpecifiedTests=false"

预期：
  [INFO] Tests run: 3, Failures: 0, Errors: 0, Skipped: 0
  [INFO] BUILD SUCCESS

耗时约 20 秒左右（其中一个用例要故意闲置 17 秒来验证心跳保活，
不是卡住了，别急着 Ctrl+C）。


【踩坑提醒】PowerShell 下 -D 参数必须加引号！
   写 "-Dtest=XXX"   而不是  -Dtest=XXX
   否则 PowerShell 会在点号处拆参数，报
   "Unknown lifecycle phase .failIfNoSpecifiedTests=false"。
   在 Linux/macOS 的 bash 里不加引号也没问题。


---------------------------------------------------------------------
六、操作二：手动启动服务器 + 客户端 UI（当前仅能验证服务器）
---------------------------------------------------------------------

第 1 步：打包

  mvn -q clean package -DskipTests

产物：
  vcampus-server/target/vCampusServer.jar
  vcampus-client/target/vCampusClient.jar

第 2 步：启动服务器（占用一个终端窗口，默认监听 8888 端口）

  java -jar vcampus-server/target/vCampusServer.jar

启动成功会打印：
  vCampus Server 已启动，监听端口 8888

第 3 步：启动客户端界面（另开一个终端）

  java -jar vcampus-client/target/vCampusClient.jar

会弹出登录窗口。

【注意】如第三章所述，目前客户端界面还没接上网络层，所以：
  - 登录窗口能打开，但点「登录」不会真的连服务器；
  - 这一步目前只能用来预览界面效果，不能用来做双端联调。
  等 client 组把 UI 与 ClientSocket 接起来后，再回来补这一节。

第 4 步：停止服务器
  在服务器那个终端按 Ctrl+C。程序注册了关机钩子，会先停监听再退出。

七、双端测试覆盖了什么
---------------------------------------------------------------------

测试文件（两个，都在 server 模块的测试目录下）：
  vcampus-server/src/test/java/edu/seu/vcampus/server/ClientServerIntegrationTest.java
  vcampus-server/src/test/java/edu/seu/vcampus/server/IntegrationTestClient.java

三个用例及其含义：

  1) unauthenticatedCommandIsRejectedByConnectionLayer
     不带 token 发业务命令 → 期望 401，且连接不被断开。
     验证点：连接级鉴权生效、拒绝响应能被客户端正确配对。

  2) clientCanLoginAndLogout
     走完挑战-应答登录（100 挑战 → 110 校验）拿到 token；
     带 token 发命令 → 期望进入分发器（未注册的命令回 400，而不是 401）；
     登出（101）→ 期望 200；再用同一个 token 发命令 → 期望 401。
     验证点：登录闭环、token 生效与失效、响应 uid 回填。

  3) heartbeatKeepsIdleConnectionAlive
     登录后啥也不干，闲置超过服务端 15 秒空闲阈值，再发命令。
     期望：连接仍然活着，命令仍能正常往返。
     验证点：客户端心跳与服务端心跳命令码一致（都是 1），心跳真的在保活。

没覆盖到的（需要后续补）：
  - 多客户端并发（线程池的并发能力）
  - 客户端断线重连（ClientReconnectTask）
  - 真实数据库读写（当前是内存 DAO）
  - 客户端界面操作流程

八、如何新增一个双端用例
---------------------------------------------------------------------

不要直接写裸 socket，请复用 IntegrationTestClient（它封装了真实
ClientSocket、请求 uid 分配、按 uid 等响应、登录）。

在 ClientServerIntegrationTest 里加一个方法，例如：

  @Test
  void yourNewCase() throws Exception {
      IntegrationTestClient client = new IntegrationTestClient(s_port);
      try {
          client.connect();
          String token = client.login(ADMIN_NAME, ADMIN_PASSWORD);

          Message response = client.request(token,
                  new Message(Command.你的命令码, 你的参数));

          assertEquals(StatusCode.SUCCESS, response.getStatusCode());
      } finally {
          client.close();   // 必须关，否则连接和后台线程会残留
      }
  }

要点：
  - s_port 是 @BeforeAll 里起好的服务器端口，直接用；
  - token 为 null 表示"这条命令不带头令牌"；
  - request 返回的响应用 response.getStatusCode() / getData() 取内容；
  - 用例里不要自己 new Socket，也不要自己建 ObjectInputStream。

九、常见问题排查
---------------------------------------------------------------------

(1) 报 "Unknown lifecycle phase .failIfNoSpecifiedTests=false"
    → PowerShell 没给 -D 参数加引号，见第五章末尾提醒。

(2) 测试里报连接超时 / Connection refused
    → 服务器没起来。双端测试是自己起的（端口 0 由系统分配），若失败请看
      控制台是否有 "测试服务器退出: ..." 字样。

(3) 手工启动服务器时报 "Address already in use"
    → 8888 已被占用（可能上次没关干净）。查占用：
        netstat -ano | findstr :8888
     结束进程：
        taskkill /F /PID <上面查到的PID>

(4) 命令发出去没有任何响应，最后报"超时"
    → 优先怀疑响应的 uid 没回填。客户端是按 uid 把响应和请求配对的，
      响应若 uid 为 null，客户端匹配不上，就会表现为"超时"而不是报错。
      服务端已由 MessageDispatcher 统一回填 uid，若新写的处理器绕过
      分发器直接发响应，注意自行回填。

(5) 登录一直失败
    → 冷启动时数据库里没有任何账号，而注册命令（102）要求管理员身份，
      形成了"没有账号就无法注册账号"的死循环。详见第十章第 2 条。

(6) 连接大概 15 秒后被断开
    → 服务端对空闲连接设了 15 秒读超时，靠客户端心跳（每 5 秒一次）保活。
      如果客户端心跳没跑或命令码对不上（两端都应为 1），连接就会被断。

十、待办与已知限制（组内需要一起解决的）
---------------------------------------------------------------------

1) 客户端界面未接入网络层
   LoginFrame 目前只画界面，没有连 ClientSocket。这是双端"手动联调"
   跑不起来的唯一原因，需要 client 组补上。

2) 【阻塞演示】冷启动没有任何账号
   注册命令要求管理员会话，而库里没有账号 → 无法创建第一个用户。
   演示和联调前需要先预置一个管理员，可选做法：
     a. 服务端加启动参数（如 --init-admin）在启动时创建默认管理员；
     b. sql/vCampus.sql 里加初始化 INSERT 并让服务器从库里读；
     c. 临时办法：跑一次集成测试，它会在 @BeforeAll 里预置管理员账号。
   建议尽快选一种（a 或 b），否则每次换环境都要折腾。

3) 数据库尚未接入
   学籍模块目前用的是内存实现 StudentDaoMemory，进程一重启数据就没了。
   待 DbHelper 合入后换成 JDBC 实现。

4) sql/vCampus.sql 与实际模型不一致（会影响数据库同学）
   现有 tblUser 主键是 uId VARCHAR(8)，而代码里用户主键已经改成
   String 类型的 uuid；同时缺 tblStudentRecord 建表语句。
   详见 docs 中学籍模块接口说明第 8 节。

5) 未覆盖的场景
   多客户端并发、断线重连、真实数据库读写、界面操作流程（见第七章）。
