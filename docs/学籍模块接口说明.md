## 1. 模块范围

学籍模块负责**学生学籍档案**的查询、登记、修改、审核、注销与状态变更。

| 项目         | 内容                                                          |
| ------------ | ------------------------------------------------------------- |
| 命令码号段   | 200 – 299                                                     |
| 处理器       | `StudentMessageHandler`（实现 `MessageHandler`）              |
| 服务层       | `StudentService`（业务核心，薄网络层 / 厚业务层）             |
| 数据访问     | `StudentDao`（接口） + `StudentDaoMemory`（内存实现，占位）   |
| 服务端包     | `edu.seu.vcampus.server.student`                              |
| 公共数据载体 | `StudentProfile`、`EnrollmentStatus`、`Command`、`StatusCode` |

## 2. 通用约定

### 2.1 通信方式

- 传输层：**TCP 长连接**；
- 序列化：**Java 对象序列化**（`ObjectOutputStream` / `ObjectInputStream`），**不是 JSON、不是 HTTP**；
- 每条消息**独立完整**序列化：发送方在 `writeObject` 前会 `reset()` 清空引用缓存。自行实现收发时务必照做，否则第二次发送同一个可变对象时，对端只会拿到第一次的旧值（back-reference 陷阱）；
- 交互单元：客户端与服务端互发 `edu.seu.vcampus.common.message.Message` 对象。

### 2.2 消息信封 `Message`

| 字段         | 类型     | 说明                                                 |
| ------------ | -------- | ---------------------------------------------------- |
| `uid`        | `Long`   | 请求唯一标识，响应原样回填，客户端据此关联请求与响应 |
| `command`    | `int`    | 命令码，见第 3 节                                    |
| `statusCode` | `String` | 状态码，见 2.4；**请求中留空，仅响应使用**           |
| `data`       | `Object` | 业务数据，类型随命令码而定，见第 4 节                |
| `sender`     | `String` | 发送方标识（预留）                                   |
| `token`      | `String` | 会话令牌，**除登录外所有请求必须携带**               |

### 2.3 认证与鉴权

- 客户端登录成功后由 `SessionManager` 签发 `token`；
- 之后每个请求在 `token` 字段带上该令牌；令牌 30 分钟**滑动过期**，每次有效请求自动续期；
- `token` 缺失 / 无效 / 过期 → `statusCode = 401`，客户端应引导用户重新登录；
- `token` 有效但角色不足 → `statusCode = 403`；
- 角色取值见 `Role` 枚举：`STUDENT("学生")`、`TEACHER("教师")`、`ADMIN("管理员")`。

### 2.4 状态码（`StatusCode`）

| 常量             | 值    | 含义                                                |
| ---------------- | ----- | --------------------------------------------------- |
| `SUCCESS`        | `200` | 成功                                                |
| `BAD_REQUEST`    | `400` | 请求参数 / 格式错误（含参数类型不匹配、未知命令码） |
| `UNAUTHORIZED`   | `401` | 未登录或会话失效                                    |
| `FORBIDDEN`      | `403` | 无权限执行该操作                                    |
| `NOT_FOUND`      | `404` | 目标学籍记录不存在                                  |
| `INTERNAL_ERROR` | `500` | 服务器内部错误                                      |

> 说明：`400` 也用于「参数类型不正确」（`ClassCastException`）与「未知的学籍命令」。

## 4. 各命令详情

### 4.1 查询学籍（201 `STUDENT_QUERY`）

- **请求 `data`**：`Long` —— 学籍记录主键 `id`。
- **响应 `data`**：`StudentProfile` 对象（已软删除的记录视为不存在）。
- **状态码**：`200` 成功；`404` 记录不存在；`400` 参数类型不正确。

客户端收到 `200` 后，从响应 `data` 取 `StudentProfile`，用 `getUserUuid()` 可进一步向用户模块查询姓名等展示信息（学籍记录本身**不冗余**用户详情，只持 uuid 引用）。

### 4.2 提交学籍修改申请（202 `STUDENT_MODIFY_APPLY`）

- **请求 `data`**：`StudentProfile`，须携带 `id` 及待修改字段。
- **响应 `data`**：`String` 提示语。
- **状态码**：`200` 成功；`404` 记录不存在或参数非法。

### 4.3 审核修改申请（203 `STUDENT_MODIFY_AUDIT`）——未实现

- 当前固定返回 `400` + `data = "审核功能待权限体系合入后实现"`。
- 待审核流程（申请表单、审批记录）设计定稿后补充本节。

### 4.4 登记学籍（204 `STUDENT_REGISTER`）

- **请求 `data`**：`StudentProfile`（`id` 留空，由服务端分配）。
- **响应 `data`**：`String` 提示语。
- **状态码**：`200` 成功；`400` 记录非法（如 `userUuid` 为空）。
- 成功后可用响应中的提示语，或再发一条 `201` 查询以获得含 `id` 的完整记录。

### 4.5 注销学籍（205 `STUDENT_DELETE`）

- **请求 `data`**：`Long` —— 学籍记录主键 `id`。
- **响应 `data`**：`String` 提示语。
- **状态码**：`200` 成功；`404` 记录不存在。
- 采用**软删除**：仅置 `deleted = true`，记录仍保留在存储中，之后的查询、修改、状态变更均视其不存在。

### 4.6 修改学籍状态（206 `STUDENT_CHANGE_STATUS`）

- **请求 `data`**：`StudentProfile`，**仅需** `id` 与 `status` 两个字段，其余可为默认值。
- **响应 `data`**：`String` 提示语。
- **状态码**：`200` 成功；`400` `data` 为 null；`404` 记录不存在、已删除或 `status` 为 null。
- **`status` 取值**：`EnrollmentStatus` 枚举 —— `ENROLLED`（在读）、`SUSPENDED`（休学）、`WITHDRAWN`（退学）、`GRADUATED`（毕业）。

客户端典型用法：表格选中一行 → 取该行 `id` → 弹出状态下拉框 → 组一个只填 `id` + `status` 的 `StudentProfile` → 以 `command = 206` 发出。

## 6. 客户端对接要点

1. **UI 不直接调用 `StudentService`**。客户端进程与服务器进程分离，任何学籍操作都必须组一条 `Message` 经 socket 发出。
2. 发起请求前先设置 `token`（登录后由会话模块统一维护）；`uid` 由客户端生成唯一值，收到响应后按 `uid` 匹配回填。
3. 统一在收包回调中**先判 `statusCode`**：`401` → 跳登录；`403` → 提示无权限；`404` → 提示记录不存在；`400` → 提示参数错误；`200` → 再解析 `data`。
4. 解析 `data` 前需做**类型判断**（`instanceof`），不要盲目强转。

## 7. 数据模型

### 7.1 `StudentProfile`

| 字段            | 类型               | 说明                                              |
| --------------- | ------------------ | ------------------------------------------------- |
| `m_id`          | `Long`             | 主键，自增，服务端分配                            |
| `m_user_uuid`   | `String`           | 关联用户模块的 uuid（**仅引用，不冗余用户信息**） |
| `m_enroll_year` | `int`              | 入学年份                                          |
| `m_status`      | `EnrollmentStatus` | 学籍状态                                          |
| `m_deleted`     | `boolean`          | 软删除标记                                        |

主要方法：`getId/setId`、`getUserUuid/setUserUuid`、`getEnrollYear/setEnrollYear`、`getStatus/setStatus`、`isDeleted`、`markDeleted`、`restore`。

### 7.2 `EnrollmentStatus`

| 枚举值      | 含义 |
| ----------- | ---- |
| `ENROLLED`  | 在读 |
| `SUSPENDED` | 休学 |
| `WITHDRAWN` | 退学 |
| `GRADUATED` | 毕业 |
