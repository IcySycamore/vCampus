# 银行 UI：由基础页面逐层增加功能

当前入口：登录正式客户端 → 左侧「校园银行」。页面沿用全局米白背景、深蓝账户卡和红色主按钮。

## 第 1 层：基础结构

`client.view.bank.BankPanel` 组合页面标题、账户卡片、流水区域及底部操作反馈。
`BankAccountCard` 负责账户视觉，`BankTransactionsPanel` 负责表格和分页。
主窗口通过 `MainContentPanel` 注册页面，窄窗口支持纵向滚动。

## 第 2 层：账户概览与开户

页面读取本人的账户，显示余额、账户号、开户时间及账户状态。
未开户（B100）显示引导卡片和「开通账户」，不会把正常的未开户状态当成错误弹窗。
开户弹窗填写当前校园账号、校园登录密码、8–64 字符独立银行密码及确认密码。
校园密码复核复用已有挑战应答接口，临时验证会话不替换主窗口会话；服务端保存银行密码的加盐摘要。
账户被冻结或注销时禁用充值，仍可以查看信息。
读取失败显示提示与刷新入口；显示失败时不继续展示旧余额。

## 第 3 层：充值

`RechargeDialog` 提供来源银行卡号、来源银行卡密码、金额输入和 10 / 50 / 100 / 200 元快捷选择。
来源卡号和密码仅用于演示输入，不验证、不保存、不发送到服务端。
确认后弹出带来源卡号的连接提示，Swing Timer 计时约两秒，再调用充值 API；并未连接外部银行。
`RechargeAmount` 负责输入校验：正数、最多 9 位整数和 2 位小数，使用 BigDecimal。
提交期间禁用确认、取消及关闭，避免重复点击；成功后更新余额并刷新流水。
金额或业务错误留在弹窗内显示。超时、断线或响应异常时，提示先刷新账户核对结果，
不直接重试资金请求，因为充值尚未实现业务请求幂等。带银行密码的消费接口按用户和订单号防重复扣款，退款尚未去重。

## 第 4 层：流水筛选与分页

类型包括全部、充值、消费、返现。每页 20 条，显示总笔数及页码。
`BankTableModels` 统一转换日期、交易类型、金额与说明；收入带加号并显示绿色，消费带减号并显示红色。
提供无流水、筛选无结果及加载失败的文案。请求期间禁用筛选和翻页，避免旧请求覆盖新结果。

## 第 5 层：真实业务接线

页面 → UiTasks → client.bank.BankService → ClientMessageDispatcher → 服务端银行模块。
客户端同步 API 读取 UserService 的当前 token，401 清除共享会话，不另存 token。清理动作复用 UserService.connectionClosed(null)，不改动用户模块。
服务端入口注册 BankModule，并通过共享 SessionManager 将 token 解析为用户 UUID。
页面不持有 Socket，不直接构造 Message；现有旧回调适配器未被此页面使用。

## 验证与边界

- API 单测覆盖共享 token、401 清会话、未开户、超时与错误 uid。
- 展示逻辑单测覆盖金额输入、收支符号及清空旧表格数据。
- 真实 Socket 集成覆盖登录、开户、21 次充值、第二页、类型筛选、退出及重新登录。
- 实际截图检查覆盖未开户、零余额、充值后、小窗口与充值弹窗。
- 当前银行服务仍使用内存：重启服务端后银行账户、余额和流水不保留。
- 银行模块未实现商城订单联动、数据库持久化、真实外部银行卡支付或密码找回；客户端断线生命周期沿用主分支的公共实现。
- 银行密码用于消费扣款；查询、充值和退款不要求银行密码。连续输错五次暂停验证一分钟。
- 服务端处理中的充值不会因客户端退出而自动回滚；重新登录后应先查询余额和流水。
- 首次缺少管理员文件时，现有引导逻辑只生成模板；重启服务端后才导入该模板账号。
