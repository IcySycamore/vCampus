vCampus 启动与通信流程

分支 feature/user-management ｜ 依据 VCampusServerApp / VCampusClientApp / ServerMessageReceiverThread / ClientMessageReceiverThread 当前实现绘制 ｜ 包结构见 docs/adr/0008-package-layout.md ｜ 2026-09-11

协议速览 前提

双端共用 common.message.Message（uid, command, statusCode, data, sender, token），经 common.network.MessageStream（对象流，先写出后读入，避免握手死锁）传输。 处理器与发送器契约同处 common.message。

项 约定
uid 客户端 ClientMessageDispatcher 用 RandomGen 分配 63 位随机正整数；服务端 UidFillingSender 在响应未带 uid 时回填请求 uid（用于追踪与排查）
响应配对 按 命令码：服务端回显请求命令码，客户端 request() 以命令码为等待槽唤醒调用方， 状态码由调用方判定成败
命令码 HEARTBEAT=1；用户管理 100 / 101 / 102 / 110；学籍 201-206；图书馆 400-403；银行 601-604
状态码 200 成功 ｜ 400 命令未登记 ｜ 401 未鉴权 ｜ 403 无权限 ｜ 404 不存在 ｜ 500 服务端错误
超时 服务端 soTimeout=15s（空闲即断）；客户端连接超时 5s、读超时 30s、重试 3 次（退避 250ms→4000ms）、心跳间隔 5s（见 ClientNetworkConfig）
心跳与心跳确认（HEARTBEAT）由两端的接收线程直接处理 / 丢弃，不进入分发器， 因此不会打断「一条命令一个等待槽」的约定。

① 服务端启动 VCampusServerApp

装配顺序：模块自装配（拿到全服唯一会话表）→ 绑定端口监听 → 每连接一线程（复用线程池）。

    B --> C["new ServerSocketListener()"]
    C --> D["registerShutdownHook()"]
    D --> E["AuthModule.register(ServerMessageReceiverThread.getDispatcher())"]
    E --> E1["AuthService.getInstance()<br/>NonceManager + SessionManager + InMemoryUserRepository 各自单例"]
    E --> E2["幂等预置演示账号：001/1 学生、003/1 管理员"]
    E1 --> F["返回全服唯一的 SessionManager"]
    E2 --> F
    F --> G["StudentModule.register(dispatcher, sessions)"]
    G --> H["server.start(port)：绑定端口并开始监听"]
    H --> I{"accept() 循环"}
    I -->|"新连接（accept 阶段完成 MessageStream 流头握手）"| J["ThreadPoolManager.execute(new ServerMessageReceiverThread(stream, sessions))"]
    J --> I
    I -->|"监听已停止"| K["退出循环，s_listener = null"]
            
flowchart TD
    A["ServerMessageReceiverThread.run()（每连接一个任务）"] --> B["socket.setSoTimeout(15000)"]
    B --> C["复用 accept 阶段已建好的 MessageStream"]
    C --> D["new ServerMessageSender(messageStream)：该连接的响应通道"]
    D --> E{"messageStream.recvMessage()"}
    E -->|"心跳 HEARTBEAT = 1"| F["回 HEARTBEAT + HEARTBEAT_ACK"]
    F --> E
    E -->|"业务命令"| G{"requiresAuthentication(command)<br/>且 token 校验失败?"}
    G -->|"是"| H["回 401：同命令码 + 回填请求 uid"]
    H --> E
    G -->|"否"| I["DISPATCHER.dispatch(request, messageSender)"]
    I --> E
    E -->|"15s 空闲超时 / EOF / Socket 断开 / 反序列化失败"| J["退出循环 → finally: closeSession(messageStream)"]
  • DISPATCHER 是 ServerMessageReceiverThread 的静态字段：全服唯一， 各模块在装配期把处理器登记到它上面。
  • 鉴权白名单：USER_LOGIN(100)、USER_REGISTER(102)、 USER_LOGIN_VERIFY(110)；其余命令必须带有效 token。
  • 关机钩子：停止监听（使 accept() 退出）+ ThreadPoolManager.shutdown()， 已提交的连接任务自然跑完。

② 客户端启动 VCampusClientApp

入口只负责「装配 + 启停」；模块把自己的处理器与接线规则带走（UserModule.register）； UI 由 LoginFlow 在后台线程完成建连与登录。 

flowchart TD
    A["VCampusClientApp.main(args)"] --> B["UiTheme.applyNimbus()"]
    B --> C["SwingUtilities.invokeLater: new LoginFrame().setVisible(true)"]
    C --> D["用户输入账号/角色/密码 → LoginFlow.start(...)"]
    D --> E["后台线程 vcampus-login → perform(...)"]
    E --> F["VCampusClientApp.connect(host, port)"]
    F --> F1["new ClientMessageDispatcher()"]
    F1 --> F2["new ClientSocketListener(host, port, dispatcher)<br/>收到的消息落点 = 分发器（无中间层）"]
    F2 --> F3["dispatcher.bindSender(new ClientMessageSender(socket))<br/>出站走同一条连接，受检 IO 在此消化"]
    F3 --> F4["dispatcher.setUiCallback(new EdtUiCallback())<br/>处理器的界面更新切回 EDT"]
    F4 --> F5["UserModule.register(dispatcher)<br/>建 UserService + 登记处理器 + 登记“会话随连接失效”"]
    F5 --> F6["socket.connect()：限时连接 + 指数退避重试"]
    F6 --> F7["install()：启动 ClientMessageReceiverThread + ClientHeartbeat"]
    F7 --> G["返回 UserService（登录/登出/会话的统一入口）"]
    G --> H["userService.login(user, role, password)：挑战 - 应答三步"]
    H -->|"被拒绝 / 超时 / 连接失败"| I["VCampusClientApp.stopQuietly() 关闭连接<br/>登录面板显示原因"]
    H -->|"成功 200"| J["openMain → new MainFrame(userId, role)"]
    J --> K["主窗口复用同一条连接与内存会话"]
    K -->|"窗口关闭"| L["VCampusClientApp.stopQuietly() → socket.close()<br/>各模块随断连丢弃内存会话"]
  • 客户端没有「上下文/中间层」对象：连接由 VCampusClientApp 创建并持有， 分发器只依赖注入的 MessageSender。
  • 界面拿到的只有模块服务（UserService），拿不到、也不需要 socket。

③ 两端通信 请求 - 响应

以「登录第 ① 步：请求挑战」为例（其余命令同构）。命令码由服务端回显，客户端按命令码唤醒等待方。 

sequenceDiagram
    autonumber
    participant UI as 界面与UserService
    participant D as ClientMessageDispatcher
    participant SS as ClientMessageSender
    participant CS as ClientSocketListener
    participant SR as 服务端 ServerMessageReceiverThread
    participant SD as 服务端 ServerMessageDispatcher
    participant H as 处理器 AuthServiceHandler
    participant SVC as AuthService

    UI->>D: request(Message(USER_LOGIN, LoginRequest), timeout)
    D->>D: assignUid 用 RandomGen 取 63 位随机正整数
    D->>D: pending.put(command, 等待槽)
    D->>SS: sender().send(request)
    SS->>CS: socket.send（uid 必须已分配）
    CS->>SR: 对象流写出（MessageStream）
    SR->>SR: isHeartbeat 为真则回 ACK 并 continue
    SR->>SR: 需要鉴权且 token 无效则回 401（同命令码 + 回填 uid）
    SR->>SD: 鉴权通过后 dispatch(request, ServerMessageSender)
    SD->>SD: handlers.get(command)
    SD->>H: 命中后 handle(request, UidFillingSender)
    H->>SVC: loginChallenge(username)，签发 salt + nonce（5 分钟一次性）
    SVC-->>H: LoginChallenge
    H->>SD: sender.send(响应)，状态码 200
    SD->>SR: UidFillingSender 回填 uid 后写出响应
    SR->>CS: 对象流回传
    CS->>D: handleReceived(generation, message)
    D->>D: handleMessage 命中等待槽
    D-->>UI: 唤醒 request，返回 Message
    UI->>UI: 状态码 200 则继续第 2 步计算 proof，否则抛 AuthException
    Note over D, SD: 未登记命令码由 ServerMessageDispatcher 直接回 400
    Note over D, SD: 未通过鉴权由连接线程回 401，二者都回显命令码并回填 uid
  • 出站：UserService → dispatcher.request() → ClientMessageSender → ClientSocketListener → 服务端。
  • 入站：ClientMessageReceiverThread → ClientSocketListener.handleReceived → dispatcher.handleMessage → 等待槽或处理器。
  • 同一个命令码同时只允许一个在途请求；重复发起会顶替前一个等待方（协议约定）。
  • 唤醒等待方只看命令码，超时或断线返回 null，由调用方转成业务异常。

④ 长连接维护：心跳与断线重连 网络层

心跳用于断线检测（服务端 15s 空闲即断，客户端默认 5s 发一次），重连在后台线程按指数退避进行。 

sequenceDiagram
    autonumber
    participant HB as ClientHeartbeat 每 5s
    participant CS as ClientSocketListener
    participant RT as ClientMessageReceiverThread
    participant SR as 服务端 ServerMessageReceiverThread
    participant D as ClientMessageDispatcher

    loop 连接存活期间
        HB->>SR: Message(HEARTBEAT, null)（不带 token）
        SR-->>HB: Message(HEARTBEAT, HEARTBEAT_ACK)
        Note over RT: 心跳与 ACK 在接收线程被直接丢弃，不上抛
    end

    RT->>CS: 读线程异常（EOF / Socket / 反序列化）→ handleConnectionClosed(generation, cause)
    CS->>CS: 校验连接代次 → 停止心跳、关闭 socket、清空连接字段
    CS->>D: handler.connectionClosed(cause)
    D->>D: 唤醒全部在途请求方（视为未收到响应）
    D->>D: 通知监听者 UserService.connectionClosed，清空内存会话
    CS->>CS: 启动后台重连线程 vcampus-reconnect（有限次 + 指数退避）
    CS->>RT: 重连成功 → install(connection)：新代次 + 新接收线程 + 新心跳
重连成功后会得到新的连接代次，上一代的迟到消息被丢弃；但服务端会话与客户端内存会话都已失效， 用户需重新登录（符合「会话不落盘、不跨连接存活」的设计）。

双端类对照 对称性

职责 服务端 客户端
应用入口 / 装配与启停 server.VCampusServerApp client.VCampusClientApp
连接层 server.network.ServerSocketListener（accept + 握手） client.network.ClientSocketListener（连接 / 重连 / 关闭 + 代次）
每连接收发线程 server.network.ServerMessageReceiverThread client.network.ClientMessageReceiverThread
分发器 server.network.ServerMessageDispatcher client.network.ClientMessageDispatcher
出站通道 server.network.ServerMessageSender client.network.ClientMessageSender
处理器契约 common.message.MessageHandler client.handler.ClientMessageHandler（多一个 UiCallback）
模块装配 server.user.AuthModule / server.student.StudentModule client.user.UserModule
业务线程池 server.thread.ThreadPoolManager 无（接收线程、心跳调度器、重连线程按需创建）
心跳 应答 HEARTBEAT_ACK；15s 空闲断开 client.network.ClientHeartbeat 每 5s 发送
连接事件回调 无（线程同步处理） client.handler.UIUpdateHandler / ConnectionListener

包结构一览 ADR-0008

横切设施 + 业务模块两级划分；双端对应角色同名同层，共享契约集中放 common。 

common.message      Message / MessageSender / MessageHandler（双端共享契约）
common.network      MessageStream
common.constant     Command / StatusCode / NetworkConstant
common.random       RandomGen ｜ common.util Sha256Util
common.<业务>/        dto、entity（user / bank / library / student）

server.VCampusServerApp   入口：装配模块 + 启动监听
server.network            ServerSocketListener / ServerMessageDispatcher /
                          ServerMessageSender / ServerMessageReceiverThread
server.thread             ThreadPoolManager
server.<业务>/             user / student / library / bank（Module + Service + Handler + Dao）

client.VCampusClientApp   入口：装配模块 + 建立/关闭连接
client.network            ClientSocketListener / ClientMessageDispatcher /
                          ClientMessageSender / ClientMessageReceiverThread
                          + 心跳、重连、连接配置、优雅关闭
client.handler            ClientMessageHandler / UiCallback /
                          ConnectionListener / UIUpdateHandler
client.<业务>/             user（学籍、图书馆、商店、银行同级并列）
client.view.**            UI 组件 / 对话框 / 页面 / 主题
  • 业务模块自装配：入口只调用 <业务>Module.register(dispatcher, 共享依赖)。
  • 连接生命周期只在入口：分发器只依赖注入的 MessageSender，不持有连接。
  • 测试包与被测类同包同名，如 server.network.ServerMessageDispatcherTest。
