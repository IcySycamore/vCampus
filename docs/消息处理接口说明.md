# 消息处理接口说明（MessageHandler / MessageDispatcher）

> 状态：**草案，待确认**
> 负责：邬致远（Server 网络 / 学籍模块）
> 关联：`docs/应用层协议规定.md`（命令码 §4）、`docs/adr/0006`（通信协议与线程模型）

---

## 1. 要解决的问题

服务器收到一条 `Message`（例如 `command=201` 查询学籍）后，怎么知道该交给哪个模块、哪个函数处理？

本方案通过「一个接口 + 一个分发器」解决：**根据 command 号段，把消息自动路由到对应模块的处理器**，服务器核心不需要知道每个模块的内部实现。

---

## 2. 两个组件

### 2.1 `MessageHandler` 接口（放 `vcampus-common`）

所有业务模块共用的「处理器契约」，只有一个方法：

```java
package edu.seu.vcampus.common.handler;

public interface MessageHandler {
    /** 处理一条请求消息，返回响应消息。 */
    Message handle(Message request);
}
```

**约定**：

- 入参是请求 `Message`（含 `command` 与 `data`），出参是响应 `Message`（用 `statusCode` 标明结果）；
- `handle` 不抛受检异常：业务异常应在实现内部捕获，返回携带 `500` / `400` 的响应。

### 2.2 `MessageDispatcher` 分发器（放 `vcampus-server`）

维护 `command → MessageHandler` 的映射，提供两个方法：

```java
package edu.seu.vcampus.server.dispatch;

public class MessageDispatcher {
    // 登记：command 与处理器建立映射
    public void register(int command, MessageHandler handler) { ... }

    // 分发：按 command 找到处理器并调用
    public Message dispatch(Message request) { ... }
}
```

**行为**：

- `register`：启动阶段各模块登记自己负责的命令码；
- `dispatch`：按 `request.getCommand()` 查映射，找到就调用 `handle`；**找不到返回 400 响应**。

## 3. 各模块怎么接入（三步）

以「学籍模块」为例：

### 第 1 步：实现 `MessageHandler`

```java
public class StudentMessageHandler implements MessageHandler {
    @Override
    public Message handle(Message request) {
        switch (request.getCommand()) {
            case Command.STUDENT_QUERY:    // 201 查询学籍
                return 查询学籍(request);
            case Command.STUDENT_UPDATE:   // 202 提交修改申请
                return 提交修改(request);
            default:
                return 返回400(request);
        }
    }
}
```

### 第 2 步：在 `Command` 里登记号段常量（`vcampus-common` 的 `Command.java`）

各模块负责人在完成所属模块时，往 `Command` 里补自己的命令码常量。当前已划分：

| 区段 | 模块 | 负责人 |
| --- | --- | --- |
| 100–199 | 用户管理 | 李文湖 |
| 200–299 | 学籍 | 邬致远 |
| 300–399 | 选课 | 赵芊雅 |
| 400–499 | 图书馆 | 张芸菲 |
| 500–599 | 商店 | 魏雨霏 |
| 600–699 | 银行 | 周奥林 |

### 第 3 步：服务器启动时注册

```java
MessageDispatcher dispatcher = new MessageDispatcher();
dispatcher.register(201, new StudentMessageHandler());
dispatcher.register(202, new StudentMessageHandler());
// ... 其余模块同理
```

服务器收发循环里，收到消息后只调一次 `dispatch` 即可自动路由：

```java
Message req = stream.recvMessage();
Message resp = dispatcher.dispatch(req);
stream.writeMessage(resp);
```

## 4. 边界与注意事项

1. **接口放 common、分发器放 server**：接口要被所有模块实现，所以放 `vcampus-common`；分发是服务端行为，放 `vcampus-server`。
2. **号段不撞车**：各模块只登记自己号段内的 command，不要跨段注册。
3. **线程安全**：`MessageDispatcher` 内部用 `ConcurrentHashMap`，`register` 在启动期单线程完成，`dispatch` 被线程池的多线程并发调用，安全。
4. **未登记 command**：统一返回 400（`StatusCode.BAD_REQUEST`），不抛异常、不拖垮连接。
5. **处理器内部异常**：由各模块自己的 `handle` 捕获并转成 500 响应，不让异常穿透到网络层。
