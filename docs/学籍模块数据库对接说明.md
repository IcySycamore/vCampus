> 对接方：数据库设计 / DAO 实现同学

---

## 0. 一句话结论

学籍模块**不新增 VO / PO 类**。数据库同学直接使用 `vcampus-common` 中已有的实体
`edu.seu.vcampus.common.entity.StudentProfile` 作为持久化载体；

本模块真正需要交付给数据库同学的是三样东西：**建表 SQL + 字段映射 + DAO 语义约定**。

---

## 1. 为什么不新建 VO

### 1.1 数据库结构与本模块业务模型是一一对应的

`tblStudentRecord` 的每一行恰好对应一个 `StudentProfile` 对象，没有多表连接、
没有聚合统计、没有字段级转换。再抽一层 VO 等于把同样的字段抄写两遍，
并额外维护两份互相转换的代码，纯增加成本。

### 1.2 DAO 契约已经按实体定义好了

`StudentDao` 的方法签名（见第 2 节）返回/接收的都是 `StudentProfile`。
若改为 VO，则 `StudentService`、`StudentMessageHandler` 乃至已有的 4 个测试类
都要跟着改，等于白白多穿一层。

### 1.3 与现有模块保持一致

`User`、`BankAccount` 等实体同样直接承担了数据载体的职责，团队并未为它们单独
定义 VO。学籍模块跟随同一做法，避免同一工程里出现两套风格。

### 1.4 术语澄清

`StudentProfile` 严格来说是**实体（entity）**而不是 VO（Value Object）。
VO 的定义是「无标识、不可变、按值相等」（如坐标、金额），而 `StudentProfile`
带有主键 `m_id` 标识，属于实体。日常口语里把「数据载体」称作 VO 很常见，
但提交代码时请不要新建名为 `XxxVO` 的类，以免与既有风格冲突。

## 2. 需要实现的 DAO 接口

接口文件：`vcampus-server/src/main/java/edu/seu/vcampus/server/module/student/StudentDao.java`

实现类请命名为 `StudentDaoJdbc`，与内存实现 `StudentDaoMemory` 放在同一包下。

| 方法 | 含义 | 语义要点 |
| --- | --- | --- |
| `StudentProfile findById(Long id)` | 按主键查一条 | 记录不存在**或已软删除**时返回 `null` |
| `StudentProfile findByUserUuid(String userUuid)` | 按用户 uuid 查本人学籍 | 同上 |
| `List<StudentProfile> findAll()` | 列出全部学籍 | **只返回未软删除**的记录；无数据返回空列表（不返回 null） |
| `boolean insert(StudentProfile profile)` | 新增 | `m_id` 为 null 时由数据库自增分配，**并把分配到的 id 回填到传入对象** |
| `boolean update(StudentProfile profile)` | 按主键全量更新 | `m_id` 为 null 或记录不存在时返回 `false` |
| `boolean softDelete(Long id)` | 软删除 | 仅置 `deleted = 1`，**不物理删除数据行** |

## 3. 表结构草案

### 3.1 建表 SQL（草案）

```sql
DROP TABLE IF EXISTS tblStudentRecord;
CREATE TABLE tblStudentRecord (
  srId        BIGINT      NOT NULL AUTO_INCREMENT COMMENT '学籍记录主键',
  userUuid    VARCHAR(36) NOT NULL                COMMENT '所属用户 uuid',
  enrollYear  INT         NOT NULL                COMMENT '入学年份',
  status      VARCHAR(16) NOT NULL                COMMENT '学籍状态：ENROLLED/SUSPENDED/WITHDRAWN/GRADUATED',
  deleted     TINYINT(1)  NOT NULL DEFAULT 0      COMMENT '软删除标记：0 未删除，1 已删除',
  PRIMARY KEY (srId),
  KEY idx_student_user (userUuid)
) COMMENT='学生学籍表';
```

> 列名风格请数据库同学按团队约定统一（`sql/vCampus.sql` 里 `tblUser` 用的是
> `uId`/`uName` 这类「表前缀 + 字段」短名，本草案为了可读性未加前缀，以团队最终约定为准）。

### 3.2 Java 字段 ↔ 数据库列 映射

| `StudentProfile` 字段 | Java 类型 | 建议列名 | 列类型 | 说明 |
| --- | --- | --- | --- | --- |
| `m_id` | `Long` | `srId` | `BIGINT AUTO_INCREMENT` | 主键，插入时由数据库分配并回填对象 |
| `m_user_uuid` | `String` | `userUuid` | `VARCHAR(36)` | 引用账户 uuid；标准 UUID 为 36 字符（含横线） |
| `m_enroll_year` | `int` | `enrollYear` | `INT` | 入学年份，如 2026 |
| `m_status` | `EnrollmentStatus` | `status` | `VARCHAR(16)` | 取值见 3.3；最长常量名 `GRADUATED` 为 9 字符 |
| `m_deleted` | `boolean` | `deleted` | `TINYINT(1)` | 软删除标记 |

### 3.3 `EnrollmentStatus` 的取值与落库方式

| 枚举值 | 含义 |
| --- | --- |
| `ENROLLED` | 在读 |
| `SUSPENDED` | 休学 |
| `WITHDRAWN` | 退学 |
| `GRADUATED` | 毕业 |

**落库方式强烈建议存「常量名」字符串（如 `ENROLLED`），不要存序号 0/1/2/3。**
原因是枚举一旦调整顺序，序号含义整体错位，且历史数据不会有任何报错，
问题极难发现。若团队更倾向存中文（在读/休学/退学/毕业），
`VARCHAR(16)` 的列宽同样够用，但需要在 DAO 里做名称转换。

## 4. 语义约定（实现时必须遵守）

### 4.1 软删除

`softDelete` **只置标记不删行**，这样选课、成绩、借阅等模块对学号 / 用户 uuid
的引用不会变成悬空指针，记录事后仍可查到。

因此**所有查询都必须带上 `deleted = 0` 条件**，包括 `findById`、`findByUserUuid`、
`findAll`。这一点最容易漏，`StudentDaoMemory` 里对每个查询都做了过滤。

### 4.2 主键分配与回填

`insert` 时传入对象的 `m_id` 为 null，由数据库自增分配。**分配后必须调用
`profile.setId(生成的主键)` 回填**，因为调用方（`StudentService.registerStudent`）
依赖这一行为。JDBC 实现可用 `Statement.RETURN_GENERATED_KEYS` 或
`SELECT LAST_INSERT_ID()`。

### 4.3 查询不得返回 null 列表

`findAll` 在无数据时应返回**空列表**，不要返回 null，否则调用方需要额外判空。

## 5. 待统一的两个问题（会阻塞 DAO 实现）

### 5.1 学籍表引用 `tblUser` 的哪一列作为用户标识？

现状不一致：

- `sql/vCampus.sql` 中 `tblUser` 的主键是 `uId VARCHAR(8)`（登录 ID）；
- 而代码里用户主键已演进为 `String` 类型的 **uuid**（36 字符），
  `StudentProfile.m_user_uuid` 引用的正是这个 uuid。

两条路：

1. 学籍表引用 **uuid**：需要先给 `tblUser` 增加 uuid 列并建立唯一索引
   （或直接把主键换成 uuid），同时同步调整 `sql/vCampus.sql` 与用户模块；
2. 学籍表引用 **`uId`**：则代码里 `m_user_uuid` 的语义与命名都要改，
   并同步修改学籍模块已有的实体与测试。

**在群里与认证组确认走哪条之前，DAO 无法定稿。**

### 5.2 枚举落库方式

见 3.3。请与数据库同学确认后写进设计说明，避免各模块各存一套。

## 7. 实现完成后如何自测

现有 `StudentDaoMemoryTest` 的用例覆盖了上述全部语义（含软删除过滤、主键回填、
不存在时返回 null 等），**可直接作为 JDBC 实现的行为基准**：

- 路径：`vcampus-server/src/test/java/edu/seu/vcampus/server/module/student/StudentDaoMemoryTest.java`
- 建议做法：把该测试的用例在 `StudentDaoJdbcTest` 中针对真实数据库重跑一遍，
  保证两种实现对同一组输入给出一致结果。

回归验证：DAO 完成后跑全量 `mvn test`，确认 `StudentServiceTest`、
`StudentMessageHandlerTest` 等既有测试仍然全绿。
